# OAuth callbacks redirect to the client with a single-use handoff code

> Superseded-by: [ADR-0016](0016-native-social-login-server-side-token-verification.md) — native social login with server-side token verification.

Login and link OAuth callbacks respond to browser clients with a 302 redirect to a configured client callback URL carrying a single-use, short-lived (~60s) handoff code, which the client exchanges for the JWT session via a new `POST /auth/handoff` — instead of responding with the session as JSON. We chose this because the front-end is a Capacitor mobile app (plus an `ionic serve` browser dev client) that opens the OAuth flow in the system browser: a JSON body landing in that browser tab is unreadable by the app, while the industry-standard client-side alternative (AppAuth/PKCE per RFC 8252, app-as-OAuth-client) is unavailable for Instagram (no PKCE; the token exchange requires the client_secret), which would force two auth architectures. The handoff code mirrors OAuth's own authorization-code step: a `handoff_codes` table of single-use, short-lived rows — a deliberate sibling of `refresh_tokens`, extending ADR-0011's accepted server-side session state rather than contradicting its statelessness — so no long-lived token travels in a spoofable custom-scheme URL. Trade-offs: an extra table and endpoint to maintain, the callback tests change shape, and custom-scheme interception remains possible in dev; prod hardening is App Links/Universal Links, deliberately deferred. The JSON session response remains for direct (non-browser) clients and tests; the redirect target comes from config so the same mechanism serves the custom-scheme app URL and the web-dev client URL.

# PostgreSQL with PostGIS for the database

The database is PostgreSQL with the PostGIS extension. We chose this because the feed's core query is geospatial (rank published listings by distance to the viewer, blended with recency), and PostGIS provides indexed `geography` types and `ST_Distance` that make that a single efficient query. The schema is relational (User → Listings → Bids → Sticker → Album), which Postgres handles cleanly; the polymorphic Bid (money/trade/both) is handled with nullable columns or JSONB rather than abandoning the relational model. We rejected MongoDB (less rigorous constraints, weaker geo+recency ergonomics) and plain Postgres without PostGIS (no distance indexing — every feed query scans and computes, painful at scale). The Docker dev environment uses the `postgis/postgis` image. The trade-off is the PostGIS learning curve and extension management, accepted for first-class geospatial queries.

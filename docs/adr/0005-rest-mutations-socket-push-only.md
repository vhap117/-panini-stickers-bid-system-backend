# REST mutations with Socket.IO as push channel only

All state mutations (placing a bid, sending a chat message, accepting a bid, publishing a listing) happen via REST endpoints that validate, persist, and then emit real-time events over Socket.IO to the relevant room. Socket.IO is purely the push channel; no business logic or bid/chat submission happens inside socket handlers. We chose this over submitting bids and chat through Socket.IO directly because it keeps write operations stateless, retryable, and testable without a socket connection, and avoids duplicating auth and validation logic between REST and socket handlers. The trade-off is a client-side concern: the client needs both an HTTP client and a socket connection, and must correlate its POST response with the subsequent broadcast — a small cost for a clean server architecture.
